# Django ORM: Q, F, aggregate, annotate, distinct — подробный конспект

Продолжение конспекта по QuerySet. Модели те же: `Category`, `Tag`, `NewsLinks`, `NewsImage`, `News`.

Импорты, которые понадобятся во всех примерах:

```python
from django.db.models import Q, F, Count, Sum, Avg, Max, Min
from django.utils import timezone
import datetime
```

---

## 1. `Q` объекты — сложные условия (OR, AND, NOT)

### Проблема, которую решает `Q`

Когда ты пишешь несколько условий через запятую в `filter()`, они соединяются через **И (AND)**:

```python
News.objects.filter(category__name='Спорт', views__gt=100)
# новости, где категория = Спорт  И  просмотров больше 100
```

Но что если нужно **ИЛИ (OR)**? Просто через запятую это не сделать — вот тут и нужен `Q`.

### Синтаксис

`Q(поле__лукап=значение)` — это условие, "завёрнутое" в объект, которое можно комбинировать операторами:
- `|` — ИЛИ (OR)
- `&` — И (AND, то же самое что запятая в filter, но иногда нужно явно)
- `~` — НЕ (NOT)

### Примеры

**OR — новости из категории "Спорт" ИЛИ с тегом "олимпиада":**

```python
News.objects.filter(
    Q(category__name='Спорт') | Q(tags__name='олимпиада')
).distinct()
```

**Комбинация OR и AND — (категория "Спорт" ИЛИ "Политика") И просмотров больше 500:**

```python
News.objects.filter(
    (Q(category__name='Спорт') | Q(category__name='Политика')) & Q(views__gt=500)
)
# скобки здесь обязательны — иначе Python применит & раньше |, и логика сломается
```

**NOT — все новости, кроме тех, что от автора "Админ":**

```python
News.objects.filter(~Q(author='Админ'))
# то же самое, что и News.objects.exclude(author='Админ'),
# но ~Q() удобен, когда NOT — только часть большого условия
```

**Практический пример — поиск по сайту** (ищем текст сразу и в заголовке, и в контенте):

```python
search_term = 'парк'
News.objects.filter(
    Q(title__icontains=search_term) | Q(content__icontains=search_term)
)
```

**Ещё пример — новости за сегодня ИЛИ новости без категории (нужно проверить в админке):**

```python
today = timezone.now().date()
News.objects.filter(
    Q(date__date=today) | Q(category__isnull=True)
)
```

### Когда `Q` не нужен

Если у тебя просто несколько условий через "И" — обычный `filter(a=1, b=2)` короче и понятнее. `Q` нужен именно тогда, когда в игру вступает **ИЛИ** или **НЕ** внутри одного запроса.

## 2. `F` объекты — сравнение и работа с полями "на уровне базы данных"

### Проблема, которую решает `F`

Обычно, когда мы хотим сравнить поле со значением из Python, мы сначала читаем объект в Python, потом сравниваем/меняем и сохраняем — это два похода в базу и есть риск гонки данных (race condition), если два пользователя делают это одновременно.

`F` позволяет **ссылаться на значение поля прямо в SQL-запросе**, не вытаскивая его в Python.

### Пример 1: атомарное увеличение счётчика просмотров

Плохой вариант (два запроса, риск потери данных при параллельных запросах):

```python
news = News.objects.get(pk=1)
news.views = news.views + 1   # прочитали значение в Python
news.save()
```

Хороший вариант — через `F`, всё происходит одним SQL-запросом на стороне БД:

```python
News.objects.filter(pk=1).update(views=F('views') + 1)
```

Это классический пример именно для твоей модели `News` — счётчик просмотров новости стоит увеличивать именно так.

### Пример 2: сравнение двух полей одной модели

Допустим, у новости было бы поле `updated_at` и `date` (они у тебя уже есть). Найдём новости, которые обновлялись **позже**, чем дата публикации (то есть их редактировали после выхода):

```python
News.objects.filter(updated_at__gt=F('date'))
```

Без `F` это было бы невозможно сделать одним запросом — пришлось бы сравнивать в Python.

### Пример 3: сортировка/фильтрация по разнице между полями

```python
from django.db.models import F, ExpressionWrapper, DurationField

News.objects.annotate(
    edit_delay=ExpressionWrapper(F('updated_at') - F('date'), output_field=DurationField())
).filter(edit_delay__gt=datetime.timedelta(hours=1))
# новости, которые отредактировали спустя больше часа после публикации
```

(Про `ExpressionWrapper` можно не запоминать сразу — это уже продвинутый уровень, показал для полноты картины.)

## 3. `aggregate()` — одно агрегированное значение по всему QuerySet

`aggregate()` считает что-то по **всему набору объектов** и возвращает **словарь** (не QuerySet и не объект модели).

Основные агрегатные функции: `Count`, `Sum`, `Avg`, `Max`, `Min`.

### Примеры

**Сколько всего новостей в базе:**

```python
News.objects.aggregate(Count('id'))
# {'id__count': 214}
```

**Дать результату понятное имя:**

```python
News.objects.aggregate(total=Count('id'))
# {'total': 214}
```

**Сумма и среднее просмотров по всем новостям:**

```python
News.objects.aggregate(total_views=Sum('views'), avg_views=Avg('views'))
# {'total_views': 45210, 'avg_views': 211.3}
```

**Самая свежая и самая старая новость (по дате):**

```python
News.objects.aggregate(newest=Max('date'), oldest=Min('date'))
```

**Агрегация с фильтром "до" — сначала фильтруем, потом считаем:**

```python
News.objects.filter(category__name='Спорт').aggregate(avg_views=Avg('views'))
# средние просмотры только у новостей категории "Спорт"
```

### Важно понимать разницу: `aggregate()` vs `annotate()`

- `aggregate()` — **одно число/словарь на весь QuerySet**. "Сколько всего просмотров у ВСЕХ новостей?"
- `annotate()` — **число для каждого объекта отдельно**. "Сколько новостей у КАЖДОЙ категории?"

---

## 4. `annotate()` — агрегация "для каждого объекта"

`annotate()` добавляет к каждому объекту QuerySet вычисленное поле — обычно результат агрегатной функции по связанным объектам.

### Пример 1: сколько новостей в каждой категории

Помнишь, в предыдущем конспекте был вариант через цикл:

```python
for category in Category.objects.all():
    print(category.name, category.news.count())
# для КАЖДОЙ категории — отдельный SQL-запрос (N+1 проблема!)
```

Через `annotate()` — **один** SQL-запрос на все категории сразу:

```python
categories = Category.objects.annotate(news_count=Count('news'))
for category in categories:
    print(category.name, category.news_count)
```

Это гораздо эффективнее — ты будешь часто использовать `annotate()` именно для таких сценариев.

### Пример 2: сколько тегов у каждой новости

```python
News.objects.annotate(tags_count=Count('tags')).order_by('-tags_count')
# новости, отсортированные по количеству тегов (сначала самые "тегированные")
```

### Пример 3: сколько изображений в галерее у каждой новости

```python
News.objects.annotate(images_count=Count('images'))

# найти новости, у которых больше 3 изображений в галерее
News.objects.annotate(images_count=Count('images')).filter(images_count__gt=3)
```

### Пример 4: категории с суммой просмотров всех их новостей

```python
Category.objects.annotate(total_views=Sum('news__views')).order_by('-total_views')
# самая "популярная" категория — та, у которой суммарно больше всего просмотров
```

### Пример 5: категории без единой новости (используем `annotate` + фильтр по 0)

```python
Category.objects.annotate(news_count=Count('news')).filter(news_count=0)
# категории-"пустышки", которые можно почистить в админке
```

### Про `distinct` внутри `annotate` с `ManyToMany`

Если аннотируешь `Count()` по полю, которое связано ещё с одним `ManyToMany` или обратным `ForeignKey`, числа могут задваиваться из-за JOIN'ов. В таких случаях используют `Count('поле', distinct=True)`:

```python
Category.objects.annotate(
    news_count=Count('news', distinct=True),
    # если бы тут была ещё одна m2m-аннотация — без distinct=True числа бы задвоились
)
```

Это тонкость, с которой ты столкнёшься не сразу, но полезно знать, что она существует.

## 5. `distinct()` — убрать дубликаты

Дубликаты в QuerySet чаще всего появляются, когда фильтруешь по `ManyToMany` или обратному `ForeignKey` — под капотом Django делает `JOIN`, и если у объекта несколько "совпадений" в связанной таблице, он попадёт в результат несколько раз.

### Пример проблемы

```python
# у новости может быть несколько тегов, попадающих в фильтр,
# и тогда она появится в результате более одного раза
News.objects.filter(tags__name__in=['экология', 'экономика'])
# новость с ОБОИМИ тегами попадёт в список ДВАЖДЫ
```

### Решение

```python
News.objects.filter(tags__name__in=['экология', 'экономика']).distinct()
```

### Ещё пример — новости с несколькими изображениями

```python
News.objects.filter(images__file__isnull=False).distinct()
# без distinct() новость с 5 картинками попала бы в список 5 раз
```

### Когда `distinct()` НЕ нужен

- В обычных `filter()` без обращения к `ManyToMany`/обратным `ForeignKey` — дублей и так не будет.
- В `aggregate()`/`annotate()` дубли считаются автоматически внутри агрегатной функции — там своя логика (`Count(..., distinct=True)`), а не общий `.distinct()` в конце цепочки.

**Правило на практике:** если после фильтра по `tags__...` или похожим связям в результатах видишь повторяющиеся объекты — добавляй `.distinct()` в конец цепочки.

## 6. Итоговый комплексный пример — всё вместе

Задача: найти топ-3 категории по средним просмотрам новостей за последние 30 дней, у которых хотя бы 5 новостей, исключая новости автора "Админ":

```python
Category.objects.annotate(
    news_count=Count(
        'news',
        filter=Q(news__date__gte=timezone.now() - timezone.timedelta(days=30))
              & ~Q(news__author='Админ'),
        distinct=True,
    ),
    avg_views=Avg(
        'news__views',
        filter=Q(news__date__gte=timezone.now() - timezone.timedelta(days=30))
              & ~Q(news__author='Админ'),
    ),
).filter(news_count__gte=5).order_by('-avg_views')[:3]
```

Здесь сразу используются: `annotate`, `Count` и `Avg` с параметром `filter=` (условная агрегация), `Q` с `&` и `~`, обычный `filter()` по аннотированному полю, `order_by()` и срез `[:3]`.

Это уже довольно "взрослый" пример — не обязательно понимать его весь сразу, но полезно увидеть, как всё изученное складывается в один рабочий запрос.

## 7. Шпаргалка

| Что нужно | Инструмент |
|---|---|
| Условие "ИЛИ" / "НЕ" в фильтре | `Q()` |
| Сравнить поле с другим полем / атомарно обновить поле | `F()` |
| Одно число по всему QuerySet ("сколько всего") | `aggregate()` |
| Число для каждого объекта отдельно ("сколько у каждого") | `annotate()` |
| Убрать дубли после JOIN по m2m/обратному FK | `distinct()` |
